# What changed from 001, and why

001 = our Qwen3.6-27B reproduction of the Story Imprinting helpful-vs-dismissive organisms (24 Oct 2026). The recipe,
the evaluation protocol, the judge prompts and the estimands are unchanged unless listed below.

## Kept exactly
- **Recipe:**
  - LoRA r32 / α64 / dropout 0;
  - AdamW(0.9, 0.999, eps 1e-8, wd 0), lr 5e-4;
  - 10-step linear warmup then cosine to 0;
  - effective batch 32 = micro 4 × accum 8, one epoch;
  - data order `random.seed(seed); random.shuffle(range(N))`;
  - loss = summed token CE ÷ supervised tokens per optimizer step;
  - grad clip 1.0;
  - logits at supervised positions only, chunked, bf16 lm_head output cast to fp32;
  - snapshots at 25/62/125/188 + final;
  - replay option (006) kept as-is.
- **Evaluation:**
  - the same 200 scripts (two frozen sets of 100);
  - turn 3 = prohibition + question (trigger) or question (control);
  - default = no system turn; dismissive = Story Imprinting Table 7 verbatim;
  - own-history 5 turns, top-p 1, one seed per (tag, script, persona, trigger, turn) shared across models;
  - samplers: T 0.7 / 512 tokens (primary), T 1 + min-p 0.05 on 100 held-out trigger scripts, unrestricted T 1 on 50
    held-out default trigger scripts;
  - step-125 evaluation.
- **Judges:** GLM-5.3-flash (reasoning low) + DeepSeek-v4.1-flash-1017 (reasoning off), the same provider routing,
  one combined call. The prompt is byte-identical to 001's on 25 random conversations (tested). Scores are
  logprob-weighted at the value token.
- **Thresholds and estimands:**
  - habit ≥ 5, garbled < 6.5, coherent ≥ 7, valid = coherent ∧ ¬garbled ∧ ¬role-break(both);
  - affinity, interaction, trigger specificity;
  - paired bootstrap over scripts (1,000);
  - lexical cross-check;
  - judge agreement.
- **Health panel metrics:** entropy, top-1, tail20, tailB20, KL both ways, NLL, argmax agreement. Token-weighted per
  set plus per item.

## Changed
| Change | Why |
|---|---|
| Everything model-specific moved to `configs/models/<name>.json`: HF id + pinned revision, dtype, chat-template kwargs, render mode, end-of-turn token, persona placement, LoRA targets, vLLM options, LoRA transform | Port to Qwen3-32B and Gemma 4 without code edits. `qwen36_27b` reproduces 001. |
| All paths come from `configs/paths.json` / `paths.local.json` / `--paths`. The key is read from a configurable `.env`. | 001 hard-coded paths on its own machine. |
| Rendering is generalized into `ChatFormat`. `template` mode = 001's encoder: the full render must start with the prompt. New `concat` mode = prompt + content + end-of-turn. The mask rule is now "supervised = after the prompt through the last end-of-turn token". | Gemma 4's generation prompt (thinking off) contains an empty thought channel `<\|channel>thought\n<channel\|>`, which its final-assistant render lacks, so 001's prefix assertion cannot hold. Concat trains on exactly the token stream used at evaluation. For Qwen the mask rule equals 001's "mask the trailing newline": 001's supervised-token counts and golden rows reproduce exactly (A 5,590,115, B 5,589,452). |
| Final-logit softcapping is applied in the chunked loss and in the health panel | 001 called `lm_head` directly. That is correct for Qwen but silently wrong for Gemma (softcap 30). |
| `train.py` runs a forward check before training: the chunked loss path vs the HF model's own forward on one row, asserting a mean absolute NLL difference below 0.02 | Catches a wrong backbone path or a missing softcap on a new architecture before any GPU-hours are spent. |
| `train.py --max_steps N` also saves `stepN/` | Smoke runs produce a loadable adapter for the end-to-end test. |
| 001's `remap_lora_for_vllm.py` becomes `prepare_lora.py`. Its transforms are none (Qwen3-32B), a prefix remap (Qwen3.6, bit-identical to 001's copies, tested), and `gemma4_k_eq_v` | vLLM loads Gemma 4's k_eq_v full-attention layers by copying the k_proj base weight into the V slot but does not copy LoRA weights. The fix adds v_proj LoRA tensors equal to the k_proj ones, matching HF's V. Found by reading vLLM 0.30.0's `gemma4.py`; not GPU-tested. |
| Health panel: only the 200 prompts are shipped; replies are regenerated by each model's untrained parent (`queue_evals health_texts`, the same T 1 / 1536-token settings) | 001's panel file held Qwen3.6-27B parent replies. The panel must measure change around the model's own parent. |
| Stories and judge rubrics are fetched at pinned revisions with sha256 checks (`scripts/fetch_data.py`) | Neither source has a licence. The rubric files also carry a benchmark-canary header, so neither is redistributed in a public repo. |
| `analyze.py` adds the **in-role interaction**: habit ∧ valid ∧ ¬rb_either, counted over all conversations of the cell. It also adds `contrasts_unpaired` and `--assignments` | Requested; separates habits shown in proper chat form from story-form or role-break replies. Every 001 output is reproduced exactly: 3,068 summary values and 427,000 per-conversation values (tested). |
| Eval additions: optional 2048-token reply cap (100 held-out trigger scripts, secondary); `--smoke`; default `max_model_len` 16384 (001: 8192); per-request `max_tokens` clamped and counted if a request would exceed it; the worker skips empty batches; `--job` one-shot and `--drain` modes | The 2048 cap needs a longer context. The other changes support a remote, unattended runbook. |
| Every generated reply records `tail20`: sampled tokens with raw-distribution rank > 20, from vLLM's sampled-token rank (`logprobs=0`, `logprobs_mode=raw_logprobs`). `analyze.py` reports the pooled sum(tail20)/sum(n_tok) per model × sampler condition (`sampled_tail20`). `health.py` reports it for the parent's panel texts. `--no_tail20` switches it off. | Requested by the coordinator. On DeepSeek (009) the trained model samples ~16% of tokens outside its top 20 at T 1 vs 0.01% for the parent, matching the corpus's 15.8% out-of-top-20 share. This tests the same relation on Qwen. It adds new fields only: the 001 parity is unchanged (re-tested). |
| Conversations are stored in logical form (system persona first); the model config decides placement (`system` or `prepend_user`) | Gemma 4 and both Qwens support a system role. The fallback is for templates that lack one. The judge always sees the same structure. |
| The spend ledger now records a job tag per call. Each judge run appends `<judgments>.spend.jsonl`. Default cap $40 for this machine's ledger. | Per-job spend logging was requested. 001's cap belonged to a shared project ledger. |
| Worker `gpu_memory_utilization` default 0.85 (001: 0.45) | 001 shared its GPU with training; here nothing else runs at the same time. |
| New tools: `golden_render_test.py`, `check_lora_keys.py` (meta-device LoRA targets + vLLM name mapping), `tests/test_worker_cpu.py` (worker job logic with a dummy engine), `compare_analysis.py`, `sample_conversations.py`, `report_summary.py`, `scan_secrets.py`, `push_adapters_hf.py`, `collect_results.py`, `download_model.py` | The remote agent can verify each stage cheaply and send results back. |

## Dropped
- `--match_tokens` (experiment 005) and the `tokgen` worker job (experiment 010): not part of 001.
- `gen_eval.py`, `gen_single.py`, `vllm_parity.py`: their logic lives in the worker's `eval` / `single` / `parity`
  jobs, which is how 001 actually ran.
- `vllm-lens` (activation capture for later experiments): unused by this pipeline.
- `fla` (flash-linear-attention) from the default training requirements: Qwen3-32B and Gemma 4 have no Gated DeltaNet
  layers. Only `qwen36_27b` needs it.
- 006's replay-prompt builder: replay rows must be regenerated by the new parent if replay is used.
